# 200 — 验收标准

> [Qwen 2026-08-10] 每条标准必须可在浏览器中验证。

## AC-1：一键启动

**验证命令**：
```bash
node showcase/server.mjs
```

**通过条件**：
- 终端输出监听端口（如 `Server running on http://localhost:3000`）
- 浏览器打开该地址，看到完整页面（无白屏、无 404）
- 3 秒内启动完成

## AC-2：搜索功能可用

**验证步骤**：
1. 打开浏览器页面
2. 在搜索框输入"产品经理"
3. 点击搜索按钮或按回车

**通过条件**：
- 页面显示搜索结果卡片（≥ 1 条）
- 每条卡片包含：来源文件名、段落标题、相关度分数、原文片段
- 结果与 `node kb/search.mjs "产品经理"` 的终端输出一致

## AC-3：搜索结果视觉质量

**验证步骤**：搜索"RAG 知识库"

**通过条件**：
- 结果卡片有清晰的视觉层次（标题 > 分数 > 片段）
- 原文片段不超过 200 字（有截断）
- 搜索关键词在片段中高亮显示
- 无结果时显示友好提示（不显示空白或错误）

## AC-4：能力分析报告可视化

**验证步骤**：滚动到"核心能力"区域

**通过条件**：
- 看到 11 个能力维度的柱状图/条形图
- 每个柱子标注了能力名称和出现率百分比
- "大模型技术理解"和"项目管理与协作"并列最高（100%）
- 图表在笔记本和手机屏幕上都完整可见（不横向溢出）

## AC-5：Agent 工作流展示

**验证步骤**：滚动到"Agent 工作流"区域

**通过条件**：
- 看到 6 个角色（premise-overturner、assumption-challenger、range-creep-guardian、test-designer、metric-gate、rollback-planner）
- 每个角色有名称和一句话说明
- 角色之间有流程关系的视觉指示（箭头/连线/顺序排列）

## AC-6：多 AI 协作展示

**验证步骤**：滚动到"多 AI 协作"区域

**通过条件**：
- 看到三个 AI 工具（Qwen/DeepSeek/Codex）的分工说明
- 看到至少一个任务（001-kb-retrieval）的进度状态
- 流程关系清晰（规划 → 编码 → 审查）

## AC-7：响应式布局

**验证步骤**：
1. 笔记本浏览器全屏打开
2. 缩小窗口到手机宽度（~375px）或用 DevTools 模拟

**通过条件**：
- 桌面端：搜索结果为横排卡片（2-3 列）
- 手机端：搜索结果为纵排卡片（单列堆叠）
- 柱状图不横向溢出，文字不截断
- 无水平滚动条

## AC-8：零新依赖

**验证命令**：
```bash
cat showcase/package.json 2>/dev/null || echo "NO_PACKAGE_JSON"
```

**通过条件**：
- 不存在 `showcase/package.json`（不引入新依赖），或
- 存在但 `dependencies` 为空
- 后端仅用 Node.js 原生 `http` / `fs` / `path` 模块

## AC-9：现有代码未被修改

**验证命令**：
```bash
git -C kb diff --name-only HEAD -- lib/ search.mjs test/
```

**通过条件**：
- 无输出（kb/ 下的核心代码未被修改）

## AC-10：页面加载性能

**验证步骤**：打开 DevTools → Network → 刷新页面

**通过条件**：
- 首次加载所有资源总大小 < 500KB
- 页面完全渲染（LCP）< 2 秒
- 搜索请求响应时间 < 500ms
