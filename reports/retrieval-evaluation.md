# 检索评测报告 · AI PM Job Retrieval Lab

> 评测对象：TF-IDF 词法检索基线（jieba 中文分词 + 余弦相似度 + Top-K）
> 评测集：50 题（`kb/eval/questions.json`）· 语料：11 份岗位 JD（`kb/jobs/*.md`）
> 本报告对应 `kb/eval/results/baseline-tfidf.json`（基线快照）。

## 一、语料与指纹

- 语料边界：`kb/jobs/*.md` 共 **11 份**岗位 Markdown（`lib/indexer.mjs` 的 `listJobFiles` 决定，排除 `README.md` / 隐藏文件 / 非 `.md`）。
- 切块：按 `##` 标题切块，前言并入首个小节 → **44 个 chunk**。
- **语料指纹：`d44eec111a5f7e20`**（对 11 份语料的「相对路径 + 内容」做 sha1 取前 16 位）。指纹用于核对「这份基线对应哪一版语料」——语料漂移时指纹必变，此时旧基线失效，需重新生成。

## 二、评测集设计

50 题四类（锚点全部限定 `kb/jobs/` 下的 11 份语料，经读文校准可答）：

| 类别 | 数量 | 说明 |
| --- | --- | --- |
| exact_match | 15 | 精确锚点（公司 + 岗位 / 工具 + 要求），如「京东 算法产品经理」 |
| concept | 15 | 概念题（Agent / RAG / Prompt / 数据驱动 等） |
| cross_doc | 10 | 跨文档题（哪些岗位要求 SQL / Python / 大模型平台） |
| no_answer | 10 | 无关题（天气预报 / 加密货币行情 等），其中 2 条为**近失配**（见第四节） |

难度分布：easy 22 / medium 23 / hard 5。

**探针校准方法**：每题 `expected_sources` 与 `expected_headings` 必须能在该语料 top-5 中真实到达（先读文、再回放检索验证），避免「锚点不在语料里」的假题。

## 三、指标定义

| 指标 | 定义 |
| --- | --- |
| Recall@5 | 40 道可答题中，过滤样板后 top-5 含任意 `expected_sources` 的比例（ANY 判定） |
| MRR | 首个来源命中的排名倒数均值 |
| Precision@1 | top-1 来源即命中 `expected_sources` 的比例 |
| 引用正确率 | 首个来源命中的 chunk 标题命中 `expected_headings` 的比例 |
| 无关拒绝率 | 10 道 no_answer 中被正确拒绝的比例（返回空或 top-1 分数 < 阈值 0.05） |

评测前对「原始来源 / 收录原则 / 目录」类元数据块做样板块过滤（`README` 源 + 元数据标题），否则短而密的聚合块会系统性霸榜污染指标。

## 四、结果

运行日期：2026-08-13。结果文件：`kb/eval/results/baseline-tfidf.json` 与 `current.json`（字节一致）。

| 指标 | 值 |
| --- | --- |
| Recall@5 | **1.000**（40/40） |
| MRR | **0.930** |
| Precision@1 | **0.875**（35/40） |
| 引用正确率 | **1.000**（40/40） |
| 无关拒绝率 | **0.800**（8/10） |

### 4.1 Precision@1 的 5 次非 top-1 命中（真实的判别差异）

| 题 | 查询 | top-1 实际命中 | 说明 |
| --- | --- | --- | --- |
| em02 | Apple AI 产品经理 运营 供应链 | jd-algo-pm / 加分项 | 京东岗含物流/供应链相关词，被「运营 供应链」顶到第一，Apple 在 rank2 |
| cn07 | 数据驱动 决策 指标 | baidu-databuilder / 任职要求 | 该文档同样真实要求数据驱动，但不在本题锚点集内 |
| cn11 | AI 编程 工具 原型 | china-mobile / 任职要求 | 词面重叠把移动岗顶到第一，锚点在 rank5 |
| cd04 | 哪些岗位要求 数据分析 | baidu-llm-app / 任职要求 | 该文档同样真实要求数据分析，但不在本题锚点集内 |
| cd10 | 哪些岗位要求 产品设计工具 | baidu-llm-app / 任职要求 | 该文档写「熟练使用产品经理工具」，同样符合但不在锚点集内 |

三种成因：(1) 锚点集外文档也真实符合概念（cn07 / cd04 / cd10——属评测集锚点选择的保守，而非检索错误）；(2) 词面歧义（em02 / cn11）。**Precision@1 = 0.875 是未饱和的真实读数**，说明该轴能区分检索质量，不是恒 1.0 的摆设。

### 4.2 no_answer 的 2 条近失配失败

| 题 | 查询 | top-1 | 分数 |
| --- | --- | --- | --- |
| na09 | 产品经理年薪多少 | baidu-databuilder / 岗位职责 | 0.1077 |
| na10 | 大模型岗位薪资待遇 | baidu-llm-app / 岗位职责 | 0.1188 |

成因：查询与词表**部分重叠**（「产品经理」「大模型」是高频词，df 高、idf 低）但**语义超纲**（年薪/薪资待遇是语料不含的主题），检索器把「相关但不含薪资内容」的岗位 chunk 顶到了阈值之上 → 未拒绝。这是词法检索的固有边界，也是后续语义检索引申（如「这个查询该不该拒绝」）的目标题。

## 五、饱和与判别力说明

- **Recall@5 / MRR 高是结构性饱和**：语料小（11 份 / 44 chunk）且锚点 token 特征鲜明，TF-IDF 精确命中。饱和是「锚定验证 + token 精确匹配」的结果，不造假也不夸大。
- **判别轴在 Precision@1 与无关拒绝率**：前者 0.875（5 次真实差异），后者 0.800（2 条近失配失败）。这两轴未饱和，能区分不同检索器。
- 未来对比语义检索时，需补充语义/近义改写题（语料增长后），否则 answerable 轴无法体现改进。

## 六、复现方法

```bash
npm ci                   # 根目录按 package-lock.json 锁定安装 @node-rs/jieba
npm test                   # 15 条行为测试
npm run eval               # 重跑 → 覆盖 results/current.json
node kb/eval/run-eval.mjs --name baseline-tfidf --force   # 重新生成基线快照
```

- 基线快照保护：非 `current` 的结果文件需 `--force` 才可覆盖，防止后续实验冲掉基线。
- 核对指纹：重跑后若 `corpus_fingerprint != d44eec111a5f7e20`，说明语料已漂移，本报告与旧基线不再对应新语料，需重新校准评测题并生成新基线。

## 七、结论

检索基线在 11 份岗位语料上可复现地达到 Recall@5=1.000 / MRR=0.930 / Precision@1=0.875 / 引用正确率=1.000 / 无关拒绝率=0.800。失败集中于词法检索的固有边界（近义改写、语义超纲的拒绝判别）。指标、评测集、语料指纹三者绑定，可复现可复核。
